# CounterFact

Turn repeatable visual AI failures into smaller, valid regression tests.

Phases 1-4 are implemented: controlled synthetic bar charts, strict scoring,
three-observation checks, cache and retry accounting, protected-category reduction,
fresh final confirmation and a queued FastAPI backend. Evidence comes only from
real model acquisitions. Fake adapters/transports exist only in unit tests.
There is no frontend, comparison model or Ollama adapter in these phases.

## Setup

Python 3.11+ is required; development verification used Python 3.14 on Windows.
Dependencies are pinned in `pyproject.toml`: FastAPI, Pydantic, matplotlib 3.10.8,
httpx, Uvicorn and python-dotenv; development uses pytest and Ruff. Charts use
matplotlib Agg with bundled DejaVu Sans. Byte reproducibility is verified within
the pinned rendering environment, not guaranteed across operating systems/fonts.

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
.venv/Scripts/python.exe -m pytest
```

On Linux/macOS use `.venv/bin/python` and `cp .env.example .env`.
Keep `.env` private: never commit or export credentials.

|---|---|

| GEMMA_BASE_URL | Server-side OpenAI-compatible base URL |
| GEMMA_MODEL_ID | Model ID; local recording used gemma-4-31b-it |

Google's compatible endpoint is the default. Requests use temperature 0, a fixed
versioned prompt, max_tokens 1024, and base64 PNG data URLs. Hosted inference
requires a working provider key/quota; the project does not promise free quota.
Comparison/Ollama variables in `.env.example` are reserved and not implemented.

## Generate valid input pairs

```powershell
.venv/Scripts/python.exe scripts/generate_suite.py
.venv/Scripts/python.exe -m counterfact tests/fixtures/bar_pair.json
```

The suite writes `data/suites/hard_v1.json`: seed 42, 20 synthetic families,
7 largest-category, 7 value-lookup and 6 above-threshold. Thirteen reference
answers change and seven stay unchanged. Input data is labelled synthetic;
no model predictions are generated by these commands.

Individual pair artifacts are under `data/pairs/<content-hash>/`: before/after
PNG, source chart JSON, manifest and attributed Chartographer family JSONL.
`model_evaluated=false` in the input manifest describes generated inputs; actual
inference evidence resides in observation/run tables, not that manifest flag.

Contracts: bar charts only, 2-20 categories, unique IDs and case-insensitive labels,
printable ASCII labels of at most 40 characters, nonnegative finite values up to
1,000,000. Unknown fields are rejected. Largest-category requires a unique winner
on both sides. Lookup needs value labels ON. Threshold uses strict greater-than
(equality is false); labels default OFF for threshold/largest questions. Value
changes and reorderings must be valid, target existing categories and create a net
change. Source data computes expected answers; no model-generated code executes.

## Real inference and three-observation checks

```powershell
.venv/Scripts/python.exe scripts/preflight.py
.venv/Scripts/python.exe scripts/pilot.py --limit 6 --cap 80
.venv/Scripts/python.exe scripts/pilot.py --limit 6 --cap 0
```

Preflight makes one logical acquisition, at most three outbound attempts including
retries. Pilot's first six families are balanced: two of each question type.
Every image needs three separately acquired observations: two correct means
passes, two incorrect means fails, other complete groups mean mixed. All three
slots are required. Missing slots mean inconclusive. Invalid output is separate
from wrong answers; provider failures are never task failures or cached observations.
Fails-to-passes pairs have the label mixed in the pair-status vocabulary.

Each outbound attempt, including retries, reserves budget before dispatch.
Retries apply to transient rate-limit/server/network/timeout errors only, with
bounded jittered backoff. Persistent provider errors stop evaluation, retain partial
results and are not automatically retried as another suite run.

The zero-cap command can only replay cached slots; missing slots remain incomplete.
Fresh acquisitions use a UUID suffix on the canonical group hash, preserving old
rows and timestamps. Ordinary replay chooses the newest acquisition for each slot.
Cache identity includes image bytes, question, prompt version, generation settings,
endpoint/provider, model and config revision; never keys. A cap counts attempts,
not reduction steps. Client API bodies cannot override inference configuration.

## Normalizer

SCORER_VERSION="1" remains strict: trim whitespace, strip at most one outer plain
or JSON Markdown fence, then parse the whole string as an object with only answer.
Thought blocks, extra prose/keys, malformed JSON and multiple objects are invalid_output.
Nonstandard NaN/Infinity constants and duplicate object keys are invalid_output.
No JSON search, repair or LLM scoring. Label comparison uses trim/casefold; numeric
answers use relative tolerance 1e-6 and absolute tolerance 1e-9; threshold accepts
boolean values or case-insensitive yes/no strings.

Google-hosted Gemma receives
`extra_body.google.thinking_config.thinking_level="minimal"`.
[Gemma API guide](https://ai.google.dev/gemma/docs/core/gemma_on_gemini_api) documents
minimal/high; [compatibility guide](https://ai.google.dev/gemini-api/docs/openai)
documents the extra-body field. The accepted parameter is recorded and included in
cache identity. Rejected parameters are reported without silent fallback.
The 1,024-token limit remains because original inspection found no JSON truncation.

Cached scores are recomputed from raw_text with scorer version recorded on derived
results. Historical acquisition rows are preserved. New observations save scorer
version and finish-reason/token usage metadata. Older rows lack that metadata;
it cannot be recovered. `python scripts/rescore.py` scores offline without writes
or network. Scorer v2 thought stripping was not enabled because the provider fix
removed thought output in the real preflight and balanced pilot.

## Reduction engine

```powershell
.venv/Scripts/python.exe -u scripts/minimize_real.py
```

Selects a failure from stored strict-scored observations, preferring a
correct-to-incorrect pair, otherwise a single-image wrong answer. It runs once,
with at most 60 outbound attempts and a default 600-second pre-dispatch time limit.
Group deletions progress to single deletions. Targets, unique winners on both sides,
and transformation-touched categories survive. Paired deletion affects the same
IDs on both sides. Invalid candidates consume no inference attempts. Images,
question binding and reference answers are recomputed for each valid candidate.
Only strictly smaller candidates preserving the predicate are accepted.

Search retains three attempts for fresh single-image confirmation or six for a
pair. Retries also consume these allowances; incomplete/failed confirmation stays
unconfirmed. Cancellation and time limits are checked before every attempt,
including retries. An in-flight HTTP request is not forcibly killed. Only successful
fresh confirmation permits "smallest confirmed case found"; otherwise the label is
"smallest observed candidate (unconfirmed)". No global minimality is claimed.

SQLite migrations preserve pairs and observations: v2 adds observation/run/case_result,
v3 reduction_step/regression_case, v4 durable job status. Steps survive interruption.
Self-contained cases and hashed before/after PNGs are under `data/regressions/`.
Unconfirmed exports stay labelled; the API's confirmed-regression endpoint rejects them.

The local real recording reduced a 17-category threshold failure to 2 categories,
confirmed three fresh wrong answers, used 16/60 attempts including a recovered retry,
and ended with search_completed. This is a source-grounded near-threshold error;
all answers were yes, so it is not an observed answer flip. Dynamic y-axis scaling
and small pixel margins limit causal attribution, as investigated in Phase 2c.

## Backend API

Run exactly one Uvicorn process/worker:

```powershell
.venv/Scripts/python.exe -m uvicorn counterfact.api:create_app --factory --host 127.0.0.1 --port 8000
```

Backend docs: http://127.0.0.1:8000/docs. UI: http://127.0.0.1:5173/.
One asyncio queue executes one inference job at a time, with at most four waiting;
additional submissions get 429. Runs have a fixed 120-attempt cap; minimizations 60.
On startup, old queued/running jobs and runs become interrupted, with partial evidence
retained and no automatic resume. Cancellation is idempotent, releases queued slots,
and stops subsequent attempts/retries. It waits for any current HTTP request to end.
CORS permits localhost/127.0.0.1 ports 5173 and 3000 only. No arbitrary endpoint or
filesystem-path input is accepted. This local developer API has no authentication;
run it bound to 127.0.0.1, with one worker.

| Method | Endpoint | Contract |
|---|---|---|
| GET | /api/health | Health and active/waiting counts |
| GET | /api/models | Profile names, key_present boolean, last status; never keys |
| GET | /api/suites | Known synthetic suite metadata |
| GET | /api/runs | Latest recorded runs, status, cache/live and budget metadata |
| GET | /api/runs/{id}/cases | Read-only evidence summaries for the run |
| GET | /api/runs/{id}/cases/{case_id} | Both chart hashes, questions, expected answers, observations and eligibility |
| POST | /api/runs | suite_id, model_profile, fresh=false, optional limit 1-20; 202/run_id |
| GET | /api/runs/{id} | Progress, results, cache/live counts and attempts/budget |
| POST | /api/runs/{id}/cancel | Idempotent cancellation |
| POST | /api/minimizations | run_id, case_id, optional side; 202/minimization_id |
| GET | /api/minimizations/{id} | Steps, best candidate, calls/60, cache hits, elapsed, confirmed |
| POST | /api/minimizations/{id}/cancel | Idempotent cancellation |
| POST | /api/regressions | minimization_id; returns the saved confirmed export |
| GET | /api/artifacts/{hash} | Known PNG hashes only, verified against actual bytes |

Only gemma is configured. All HTTP errors use
`{error:{code,message,retryable,details},request_id}`.
Invalid bodies return 422, unknown resources 404, incompatible states 409,
queue-full 429. Old /api/pairs preview routes were removed to match the approved
endpoint-only contract; CLI pair generation still works.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod http://127.0.0.1:8000/api/models
$body = '{"suite_id":"hard_v1","model_profile":"gemma","fresh":false,"limit":6}'
$run = Invoke-RestMethod http://127.0.0.1:8000/api/runs -Method Post -ContentType 'application/json' -Body $body
Invoke-RestMethod "http://127.0.0.1:8000/api/runs/$($run.run_id)"
```

## Phase 0-4 revalidation

The audit retains schema v4 and scorer v1. Run budget metadata now links each side to
its exact observation IDs, including replay of fresh acquisitions, so a later check
cannot retroactively change which raw responses a historical run used. Legacy runs
without these links use their acquisition snapshot as of completion. Offline rescore
uses the same provenance logic. Queue admission creates the durable job and run in
one transaction. Polling after restart reads saved budgets; model-key inspection does
not parse unrelated generation settings. None of these fixes changes inference/cache
identity or historical observation rows.

A process crash during an unfinished acquisition can leave metadata less complete than
a finished step: restored minimization attempt counts reflect persisted evidence, not
an invented reconstruction of an unrecorded in-flight HTTP request. Such jobs are
interrupted and never resumed automatically. Full completed recordings retain exact
attempt counts and fresh confirmation evidence.

## Frontend (Phase 5)

In a second terminal, from the repository root:

```powershell
npm ci --prefix frontend
npm run dev --prefix frontend
```

Open http://127.0.0.1:5173/. Vite proxies `/api` to the backend on port 8000.
The page shows existing completed evidence when available; page load makes no
inference calls. Start a run explicitly to acquire missing slots, or enable fresh
acquisition to bypass cached observations. API keys remain in the backend `.env`.
Select a case to inspect all responses as plain text. Confirmed failures can be
minimized, with a 60-attempt cap; only confirmed results can be saved and downloaded.
An existing saved minimization appears automatically for its matching case.
Disconnected polling pauses, retains evidence, and retries with bounded backoff.

```powershell
npm run build --prefix frontend
npm run typecheck --prefix frontend
```

There is no ESLint configuration in this minimal frontend. Model comparison is
explicitly marked unimplemented. The UI is local development tooling, not a public
authenticated deployment. No new real inference was performed for Phase 5 UI checks.
